# Advanced DB Final Project

Multi-service fundraising platform built with:

- `donation_user` for SQL Server users, donations, receipts, and Stripe payments
- `campaign_comment` for MongoDB campaigns, comments, likes, reports, and images
- `saga_orchestrator` for coordinated write flows
- `gateway` as the main API entrypoint
- `web` as the static frontend

## Project Structure

```text
advanced-db-final/
|- donation_user/        # FastAPI + SQL Server + Stripe
|- campaign_comment/     # FastAPI + MongoDB
|- saga_orchestrator/    # FastAPI saga service
|- gateway/              # FastAPI API gateway
|- web/                  # Static frontend
|- run-local-demo.ps1    # Starts everything locally
|- stop-local-demo.ps1   # Stops local processes
|- requirements.txt      # Root Python dependencies
```

## Prerequisites

- Python `3.11+` with `venv`
- PowerShell on Windows
- SQL Server running locally
- MongoDB running locally
- `mongosh` for MongoDB seed scripts

## Dependencies

Install everything from the root `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Dependency check:

- The root [requirements.txt](requirements.txt) already includes `stripe==15.1.0`.
- You do not need an extra `pip install stripe` if you install from the root requirements file.

## Environment Files

This repo uses several `.env` files:

- root [.env](.env): MongoDB connection
- [donation_user/.env](donation_user/.env): SQL Server, JWT, Stripe
- [campaign_comment/.env](campaign_comment/.env): Mongo DB name and gateway URL
- [saga_orchestrator/.env](saga_orchestrator/.env): internal service URLs
- [gateway/.env](gateway/.env): internal service URLs and JWT settings

Important values:

- root `.env`

```env
MONGO_URI="mongodb://localhost:27017/"
```

- `donation_user/.env`
  - set `DB_SERVER` to your SQL Server instance
  - keep `DB_NAME=donation_db` unless you change the schema target
  - configure `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, and `STRIPE_WEBHOOK_SECRET` with Stripe test keys

## One-Time Database Setup

### 1. SQL Server Setup

Create or select a database named `donation_db`, then run these scripts in order:

1. [donation_user/scripts/schema.sql](donation_user/scripts/schema.sql)
2. [donation_user/scripts/trigger_receipts.sql](donation_user/scripts/trigger_receipts.sql)
3. [donation_user/scripts/user_data.sql](donation_user/scripts/user_data.sql)
4. Optional: [donation_user/scripts/donation_data.sql](donation_user/scripts/donation_data.sql)

Notes:

- receipts for donations `>= 50` are generated by the SQL trigger
- sample seeded user noted in `donation_user/.env`: `Vesta / password!223`

### 2. MongoDB Setup

Open `mongosh` from the project root and run:

```javascript
load("campaign_comment/scripts/createdb.js")
load("campaign_comment/scripts/comment_data.js")
```

This creates:

- `charitydb`
- `campaigns` collection
- `comments` collection
- sample campaigns
- sample comments
- indexes used by the app

## Stripe Setup

Stripe is already wired into the backend and dependencies.

What you still need:

1. Put Stripe test keys in `donation_user/.env`
2. Restart the services after changing Stripe keys
3. Use Stripe test card `4242 4242 4242 4242`

For a more detailed Stripe walkthrough, see [STRIPE_SETUP.md](STRIPE_SETUP.md).

## Run the Project

Preferred option:

```powershell
.\run-local-demo.ps1
```

What this script does:

- creates `.venv` if needed
- installs `requirements.txt` unless you pass `-SkipInstall`
- generates local JWT keys in `.logs/`
- starts all FastAPI services
- starts the static frontend server
- writes logs to `.logs/`

Default URLs:

- Gateway API: `http://127.0.0.1:3000`
- Frontend: `http://127.0.0.1:5500`
- Donation service: `http://127.0.0.1:3001`
- Campaign/comment service: `http://127.0.0.1:3002`
- Saga service: `http://127.0.0.1:3003`

Useful flags:

```powershell
.\run-local-demo.ps1 -SkipInstall
.\run-local-demo.ps1 -VisibleWindows
.\run-local-demo.ps1 -Reload
.\run-local-demo.ps1 -NoWeb
```

## Stop the Project

```powershell
.\stop-local-demo.ps1
```

This stops the service processes started by `run-local-demo.ps1` and also sweeps the default ports:

- `3000`
- `3001`
- `3002`
- `3003`
- `5500`

## Manual Run Commands

If you do not want to use the helper script, activate the virtual environment first:

```powershell
.\.venv\Scripts\Activate.ps1
```

Then run each service in a separate terminal:

```powershell
python -m uvicorn donation_user.main:app --host 127.0.0.1 --port 3001
python -m uvicorn campaign_comment.main:app --host 127.0.0.1 --port 3002
python -m uvicorn saga_orchestrator.main:app --host 127.0.0.1 --port 3003
python -m uvicorn gateway.main:app --host 127.0.0.1 --port 3000
python -m http.server 5500 --bind 127.0.0.1 --directory web
```

Note:

- the helper script is easier because it also injects the required service URLs and generated JWT key paths into each process

## Common Issues

### Ports already in use

Run:

```powershell
.\stop-local-demo.ps1
```

Then start again.

### MongoDB not connecting

Check the root `.env` and make sure MongoDB is running on the `MONGO_URI` you configured.

### SQL Server not connecting

Check:

- `DB_SERVER` in `donation_user/.env`
- whether SQL Server is running
- whether `donation_db` exists
- whether your auth mode matches `DB_TRUSTED_CONNECTION`

### Stripe payment errors

Check:

- Stripe keys in `donation_user/.env`
- that you are using Stripe test cards
- the donation service logs in `.logs/`

## Notes
